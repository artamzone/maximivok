# TaskCheck — независимый контроль проекта ИВОК

## Назначение

Этот файл содержит указания для следующего агента-исполнителя. Он не заменяет `Task.md` и не разрешает автоматически начинать новые крупные этапы. Перед реализацией любой корректировки агент обязан свериться с этим файлом и согласовать неоднозначные изменения с пользователем.

## Главный приоритет проекта

Основная задача проекта — **расчёт отопления и создание сметы по отоплению** (если под словом «смены» имелась в виду именно «смета»). Водоснабжение, канализация, каталог и материалы являются сопутствующими подсистемами и не должны вытеснять отопление.

Не начинать без отдельного запроса:

- расширение сантехнических расчётов сверх уже согласованного объёма;
- включение материалов в КП/смету;
- AI-подбор товаров;
- интеграции с 1С, мессенджерами и внешними сервисами;
- авторизацию, PostgreSQL и внешнее размещение;
- новые крупные UI-рефакторинги, не связанные с основной задачей.

## Найденные проблемы, которые учитывать при следующей задаче

### P1. UI сантехники неправильно моделирует комнаты

`public/santeh.js` создаёт `roomId` из типа прибора. Из-за этого приборы не группируются по реальным комнатам, повторные приборы могут давать дубли `roomId`, а лежаки связываются с типами приборов вместо комнат.

Правильная модель:

```text
комната
  roomId
  hasRecirculation
  fixtures[]
```

Комнаты должны загружаться из последней версии отопления. Если отопления нет, UI должен разрешать ручное добавление комнат.

Эту корректировку выполнять только после отдельного согласования, если она не нужна для основной задачи отопления.

### P1. В UI смешиваются статус расчёта и статус стоимости

`report.status` и `report.costStatus` — разные статусы. Интерфейс обязан показывать их раздельно либо показывать явно агрегированный статус с пояснением.

### P1. `null` нельзя отображать как `0 ₽`

Проверить все экраны и функции форматирования стоимости. Требуемое правило:

- `null`/отсутствие суммы → «Не рассчитано» или «Неизвестно»;
- `0` → «0 ₽» только если нулевая сумма действительно рассчитана;
- рядом с неизвестной суммой показывать причину или предупреждение.

### P2. Частичный расчёт канализации

Пересмотреть строгую проверку обязательного покрытия лежаками. При отсутствии лежаков частичный расчёт точек допустим, но результат должен иметь статус `requires_engineer_review`, список недостающих параметров и предупреждение. Никаких автогенерированных трасс и приблизительных длин.

Перед изменением контракта обновить тесты и описание API.

### P2. Миграция SQLite

Добавить отдельный регрессионный тест миграции старой таблицы `calculations` в новую схему с блоками `heating`, `plumbing`, `sewage`. Проверить сохранность старых записей и возможность добавить новый расчёт.

## Обязательный порядок работы агента

1. Перед изменением определить, относится ли задача к отоплению/смете или является сопутствующей.
2. Проверить состояние Git и не трогать пользовательские перемещения файлов.
3. Прочитать локальные `AGENTS.md`, `Task.md`, `README.md` и этот файл.
4. Сначала воспроизвести проблему тестом или минимальным сценарием.
5. Внести минимальное исправление без незапрошенного рефакторинга.
6. Для изменения поведения обновить регрессионные тесты и документацию.
7. Выполнить минимум:

   ```bash
   npm test
   npm run typecheck
   git diff --check
   ```

8. Перед завершением проверить итоговый diff и перечислить оставшиеся ограничения.
9. Не делать commit, push, удаление данных или миграцию рабочей БД без отдельного разрешения.

## Критерии готовности основной задачи

Для отопления и сметы необходимо отдельно проверить:

- расчёт не выдумывает отсутствующие данные;
- частичные входы дают понятные `missingParameters`;
- стоимость известных монтажных работ считается точно в копейках;
- материалы не считаются бесплатными и не включаются в смету без согласования;
- старые версии отопления не пересчитываются после изменения цен;
- новая смета содержит снимок применённых цен;
- результат можно воспроизвести по сохранённому входу и снимку цен;
- статусы «рассчитано», «требует проверки инженера» и «невозможно» не смешиваются;
- автоматические тесты не подменяют инженерную приёмку реальных примеров.

## Открытый вопрос

В пользовательском сообщении использовано слово «смены». В текущем контексте принято рабочее предположение, что имеется в виду **смета по отоплению**. Если имелось в виду другое (например, рабочая смена или график), это нужно уточнить до реализации.
