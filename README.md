# Локальное приложение ИВОК

Реализация **TASK-01**, локального этапа **TASK-02** и части **TASK-03** из `Task.md`:

- детерминированный расчёт отопления;
- карточки клиентов и объектов;
- сохранение версий расчётов в SQLite;
- источник и статус каждого входного и вычисленного параметра;
- веб-интерфейс и CLI расчётного ядра;
- каталог san-baza и ручной выбор материалов объекта с отдельными версиями.

Авторизация, AI, внешние интеграции и автоматический подбор товаров пока не используются.

## Требования

- Node.js 22.13 или новее (для встроенного модуля SQLite);
- npm.

В окружении с `NODE_ENV=production` установите зависимости разработки явно:

```bash
npm install --include=dev
```

## Веб-приложение

Запустите локальный сервер:

```bash
npm run web
```

Откройте в браузере:

```text
http://127.0.0.1:3000
```

Сервер намеренно принимает подключения только с локального компьютера. Другой порт можно задать переменной `PORT`.

В интерфейсе можно:

1. создать карточку клиента и объекта — обязательны только имя клиента и адрес объекта; карточку можно сохранить без расчёта;
2. заполнить известные помещения и параметры; пустые поля остаются неизвестными, а не нулевыми;
3. указать общий источник и статус введённых параметров;
4. сохранить расчёт;
5. открыть сохранённый объект, отредактировать карточку и добавить новую версию расчёта;
6. посмотреть источник и статус каждого сохранённого параметра;
7. скачать исходные данные и отчёт в JSON.

**«Сохранить карточку»** сохраняет только данные клиента и реквизиты объекта. Изменения полей отопления и их метаданные эта кнопка не сохраняет.

**«Сохранить и рассчитать»** сохраняет параметры отопления и метаданные новой версией, даже если данных недостаточно для полного расчёта. Отдельного черновика параметров без расчёта пока нет.

В списке объектов отображается статус последнего расчёта или «Без расчёта». На экранах шириной до 640 px список по умолчанию свёрнут; кнопка «Показать объекты» открывает его. После выбора объекта список сворачивается.

По умолчанию база находится в `data/ivok.sqlite`. Путь можно изменить переменной `IVOK_DATABASE_PATH`. Каталог `data/` не сохраняется в Git.

Остановить сервер можно сочетанием `Ctrl+C`.

## HTTP API

| Метод и адрес | Назначение |
| --- | --- |
| `GET /api/objects` | Список сохранённых объектов |
| `GET /api/catalog?query=...&category=...&page=1` | Поиск сохранённых товаров, категории и страница из 50 позиций |
| `POST /api/objects` | Создать клиента и объект; первый расчёт можно передать необязательно |
| `GET /api/objects/:id` | Получить карточку и все версии расчётов |
| `PATCH /api/objects/:id` | Изменить карточку клиента и объекта |
| `POST /api/objects/:id/calculations` | Добавить версию расчёта |
| `GET /api/objects/:id/materials` | Объект, последняя комплектация и список её версий |
| `POST /api/objects/:id/materials` | Сохранить отдельную версию материалов по текущим ценам каталога |
| `GET /api/objects/:id/materials/:versionId` | Прочитать неизменяемую версию материалов |
| `GET /api/works` | Прочитать пять работ, цены и текущую версию справочника |
| `PUT /api/works` | Атомарно сохранить цены с проверкой версии |
| `POST /api/calculate` | Выполнить расчёт без сохранения, с текущими ценами работ из SQLite |

Все основные сущности сохраняют `organization_id`. В локальном режиме используется одна системная организация `org-local`.

## Запуск расчёта через CLI

Из файла:

```bash
npm run calculate -- examples/heating-input.json
```

Через stdin:

```bash
cat examples/heating-input.json | npm run calculate
```

Команда печатает отчёт в stdout. Ошибка JSON или входного контракта печатается в stderr, код завершения — `2`.

## TASK-03: каталог san-baza

Источник материалов — `san-baza.ru`. Файл `san-baza.xlsx` получен парсингом сайта, а не выгрузкой 1С. Скрипта парсинга в проекте пока нет.

Первый подэтап — проверка локального XLSX **без записи в SQLite**:

```bash
npm run catalog:check -- san-baza.xlsx
```

Команда читает лист `Каталог`: заголовки в строке 4 — `Категория`, `Название`, `Артикул`, `Цена, ₽`, `Единица`, `URL`; товары начинаются со строки 5. Пустые строки пропускаются. Другой порядок колонок или дополнительные непустые колонки требуют изменения формата, а не угадываются автоматически.

- Категория, название и единица — непустой текст. Пробелы по краям текстовых значений убираются; единицы не пересчитываются и не переименовываются.
- Артикул — текст или пустая ячейка. Ведущие нули сохраняются. Числовой артикул отмечается ошибкой, поскольку потерянные нули восстановить нельзя. Повторяющиеся артикулы допустимы: это не ключ товара.
- Цена — числовая ячейка с конечным значением ≥ 0 или пустая ячейка. Текстовые цены не преобразуются автоматически. Отсутствующая цена остаётся `null`; нулевая остаётся `0`. Обе ситуации отражаются отдельными счётчиками и не означают разрешение считать товар бесплатным.
- URL — HTTPS-ссылка на `san-baza.ru/catalog/` без параметров, фрагмента и учётных данных. Дубли URL отмечаются во всех конфликтующих строках; программа не выбирает одну из них автоматически. Категория не выводится из пути URL.
- Дата из заголовка не считается подтверждённой датой прайса. Характеристики, производитель и наличие не извлекаются из названий.

Результат — JSON-сводка: `rowCount`, `validRowCount`, `formatValid`, ошибки `issues` с исходными номерами строк и колонками. Счётчики `missingArticleCount`, `missingPriceCount`, `zeroPriceCount` и `repeatedArticleCount` относятся к строкам без ошибок; последний считает разные повторяющиеся артикулы после удаления краевых пробелов. Полный список товаров в CLI не печатается. Для чистого JSON без служебного вывода npm после сборки используйте `node dist/src/catalog-cli.js san-baza.xlsx`.

Код завершения: `0` — формат проверен; `2` — ошибки строк, структуры файла или аргументов; `1` — ошибка файловой системы. `formatValid` не подтверждает актуальность цен или инженерную пригодность товара. Чтение формул использует сохранённые значения XLSX, но не вычисляет их; проверка предназначена для локальной выгрузки, не для публичной загрузки произвольных файлов.

### Импорт и журнал

Согласован **частичный импорт**: корректные строки сохраняются, ошибочные пропускаются и попадают в журнал.

```bash
npm run catalog:import -- san-baza.xlsx
npm run catalog:log
npm run catalog:log -- ID_ИМПОРТА
```

`catalog:import` пишет в `data/ivok.sqlite` или путь из `IVOK_DATABASE_PATH`, как веб-приложение. Перед первым импортом в существующую рабочую БД сделайте резервную копию; при копировании файла SQLite остановите сервер. Добавляются таблицы `catalog_products` и `catalog_imports`; таблицы карточек и сохранённые отчёты не изменяются. `catalog:log` открывает БД только для чтения и не создаёт отсутствующий файл. До первого импорта журнал недоступен.

- Ключ обновления — организация + источник + URL (в представлении `new URL(...).href`). Артикул не используется как ключ. Идентификатор существующего товара сохраняется.
- Корректная строка заменяет текущие поля товара, включая пустой артикул или цену `null`. Нулевая цена сохраняется отдельно от неизвестной и не является инженерным подтверждением бесплатного товара.
- Пропущенная ошибочная строка не меняет ранее сохранённый товар. Отсутствующие в новом файле товары также не удаляются. При повторяющемся URL пропускаются все строки с этим URL; старая позиция остаётся без изменений.
- Товары и журнал сохраняются одной транзакцией. Сбой SQLite откатывает все изменения этого импорта, а не выдаётся за ошибку отдельной строки.
- Если все строки ошибочны, сохраняется только журнал с нулём загруженных строк. Если файл нечитаем, отсутствует лист/заголовок или каталог пуст, запись не начинается и ошибка показывается в stderr без записи в журнал.
- Журнал содержит имя файла, источник, время загрузки, количество новых/обновлённых/пропущенных строк, счётчики неизвестных данных и отдельный массив `issues`. Один пропущенный ряд может иметь несколько ошибок. Повторный запуск создаёт новую запись журнала; старые записи не меняются. `updatedRows` включает повторно загруженные позиции даже без изменения значений.
- В товаре сохраняется ссылка `lastImportId` на последнюю успешную загрузку этой позиции. Время загрузки не является подтверждённой датой цены сайта. Исторические версии всех полей товаров пока не сохраняются; журнал хранит сводку и ошибки.

Коды завершения **импорта**: `0` — все строки загружены; `3` — журнал сохранён, ошибочные строки пропущены (корректные уже записаны, если они были); `2` — ошибка аргументов или формата файла, импорт не начат; `1` — ошибка чтения/записи. Журнал печатается в stdout как JSON. Для чистого JSON после сборки: `node dist/src/catalog-storage-cli.js import san-baza.xlsx` или `node dist/src/catalog-storage-cli.js log [ID_ИМПОРТА]`.

### Веб-каталог и поиск

После запуска `npm run web` откройте `http://127.0.0.1:3000/catalog` (с учётом вашего `PORT`). На главной странице есть ссылка «Каталог материалов — в новой вкладке»: несохранённая карточка остаётся в исходной вкладке.

- Поиск по части названия или артикула без учёта регистра, включая кириллицу. Нажмите «Найти» или Enter; символы `%`, `_` и кавычки ищутся буквально, не как шаблон SQL.
- Категория выбирается из сохранённого каталога, фильтруется точным совпадением и применяется вместе с поиском. Смена категории сразу запускает поиск. «Сбросить фильтры» возвращает весь каталог на первую страницу.
- На странице не более 50 позиций, порядок — по имени без учёта регистра, затем URL. «Назад» и «Далее» переключают страницы. Устаревший ответ поиска не заменяет более свежий.
- Карточка показывает название, категорию, артикул, цену, исходную единицу, источник и время загрузки. Ссылка на товар открывается в новой вкладке. `null` отображается как «Цена не указана», `0` — как нулевая цена с пометкой «требует проверки».
- До первого импорта показывается пустой каталог; просмотр не создаёт таблицы каталога и не записывает данные. После CLI-импорта нажмите «Найти» — перезапуск сервера для обновления товаров не требуется.
- Ошибка загрузки отображается отдельно; старые результаты скрываются. Нажмите «Найти» для повтора. Интерфейс адаптирован к узким экранам.

API возвращает `products`, `total` (по фильтрам), `catalogTotal` (весь доступный каталог), `categories`, `page`, `pageSize`. `query` ограничен 200 символами, `category` — 1000; `page` — положительное целое с безопасным смещением. По умолчанию фильтры пустые, страница — 1. Повторяющиеся/неизвестные параметры и неверные значения дают HTTP 400. Для программно внедрённого хранилища карточек без SQLite каталог возвращает HTTP 503, а не подключается к другой базе. В обычном локальном запуске используется та же SQLite, что и для карточек, но соединение каталога открыто только для чтения.

Пока не реализованы загрузка Excel через браузер и редактор инженерных норм. Редактор цен пяти работ доступен на `/works`. Выбранные материалы сохраняются отдельно и не участвуют в инженерном расчёте отопления. Названия и характеристики не исправляются автоматически: например, текущая выгрузка содержит три товара с названием «1» (строки 251–253), требующие уточнения источника.

XLSX читает `read-excel-file` (MIT), версия закреплена в `package.json`. Синтетические тестовые XLSX лежат в `test/fixtures/catalog-*.xlsx`; их генератор `test/fixtures/generate-catalog-fixtures.py` использует только стандартную библиотеку Python. Для запуска тестов Python не нужен.

### Материалы объекта

После обновления кода перезапустите локальный сервер (`npm run web`) и обновите страницу. Сначала сохраните несохранённые данные. Для первого использования новой функции в рабочей базе рекомендуется резервная копия SQLite.

1. Откройте или сохраните карточку объекта. Под карточкой находится блок «Добавленные материалы»: нажмите «Добавить материалы» или «Перейти в материалы». Подбор откроется в новой вкладке.
2. На `/catalog?objectId=...` найдите товар и нажмите «Добавить в материалы объекта». Введите положительное количество в исходной единице; количество не подставляется автоматически. Дробные количества допустимы, автоматического пересчёта упаковок или единиц нет.
3. Повторный выбор того же товара не дублирует строку — измените её количество. Кнопка «Убрать» меняет только черновик.
4. Нажмите **«Сохранить материалы»**. Сервер заново читает все выбранные товары и цены из текущего каталога и создаёт новую версию. Цены в черновике информационные; стоимость может измениться при сохранении. Можно сохранить повторно без изменения количества, чтобы получить новую версию по свежим ценам.
5. В разделе «Сохранённые версии материалов» откройте нужную версию. Это просмотр снимка, не замена текущего черновика. «Загрузить последнюю версию» заменяет черновик; при несохранённых изменениях требуется подтверждение.

На главной странице блок **«Добавленные материалы — N позиций»** свёрнут по умолчанию и снова сворачивается при смене объекта. Кнопка перехода находится снаружи и доступна без раскрытия. Внутри — только просмотр последней сохранённой версии: номер/дата, товары, количества, единицы, цены, суммы и предупреждения. Для пустой комплектации показано «Материалы пока не добавлены»; до сохранения карточки — просьба сначала сохранить объект.

При выборе объекта, сохранении карточки и возвращении в главную вкладку обновляется только блок материалов. Несохранённые поля клиента/отопления, помещения и результат расчёта не сбрасываются. Раскрытие блока для того же объекта сохраняется. Черновик из другой вкладки не показывается: сначала нажмите там «Сохранить материалы». Ошибка чтения отображается отдельно с кнопкой «Повторить загрузку», а не маскируется пустой комплектацией. Устаревшие ответы не подменяют материалы текущего объекта.

Для этой доработки достаточно обновить страницу после сохранения текущего ввода; новые маршруты и перезапуск сервера не нужны. Последняя комплектация не привязана к версии отчёта отопления, её стоимость не прибавляется автоматически к работам.

Снимок содержит количество, название, категорию, артикул, единицу, цену, источник/URL и ID импорта каждого товара. Прежние версии не пересчитываются после обновления прайса. Если исходная единица товара изменилась, сохранение останавливается: удалите строку из черновика, выберите товар заново и проверьте количество.

Стоимость рассчитывается **на сервере**. Сумма каждой строки округляется до копейки (половина вверх) с десятичной арифметикой; известный итог складывается в целых копейках. Переполнение безопасного числового диапазона отвергается. Неизвестная цена даёт `lineTotalKopecks: null`, а не ноль. Отдельно показываются известная стоимость, число строк без цены и число строк с нулевой ценой. Это стоимость выбранного набора, не полная стоимость отопления и не утверждённое КП.

POST принимает только `{ baseVersionId, items: [{ productId, quantity, expectedUnit }] }`. `baseVersionId` — ID последней открытой версии или `null` до первого сохранения. Цены, названия и суммы от браузера не принимаются. Не более 500 строк; повторяющиеся ID и неверные количества дают HTTP 400. Неизвестный объект/версия — 404; устаревшая вкладка или изменение единицы — 409 без потери черновика. При потере связи сначала загрузите последнюю версию и проверьте, было ли сохранение выполнено.

Версии хранятся в новой таблице `object_material_versions`; она создаётся внутри транзакции при первом успешном сохранении. Просмотр до сохранения не создаёт таблицу. Запись не меняет карточку, каталог или версии расчётов отопления. Пустую комплектацию можно сохранить после подтверждения, старые версии при этом остаются в истории. Черновик живёт только в открытой вкладке; при уходе с несохранёнными изменениями браузер запрашивает подтверждение, автоматического восстановления черновика после закрытия нет.

### Справочник работ

На главной странице ссылка **«Справочник работ — в новой вкладке»** открывает `/works`. Редактируются только цены пяти работ из раздела 15 ТЗ:

| Работа | Единица | Начальная цена |
| --- | --- | --- |
| Монтаж тёплого пола | м² | 900 ₽ |
| Укладка утеплителя | м² | 100 ₽ |
| Точка водоснабжения | точка | 2 900 ₽ |
| Канализационная точка | точка | 2 500 ₽ |
| Монтаж лежака | базовая работа, не погонный метр | 12 000 ₽ |

Введите цены и нажмите **«Сохранить цены»**. Допустимы неотрицательные числа с точностью до копейки; пустое поле не означает ноль. Нулевая цена применяемой работы при положительной площади ТП даёт предупреждение `WORK_ZERO_PRICE_REVIEW` и как минимум `requires_engineer_review`. Переполнение цены или результата отклоняется.

Сохранённые цены монтажа ТП и утеплителя применяются ко всем **новым веб-расчётам**: предварительному, первому расчёту объекта и последующим версиям. Уже открытый отчёт сам не пересчитывается: нажмите «Сохранить и рассчитать», когда нужна новая версия. Изменение справочника не сбрасывает форму главной вкладки и не меняет старые JSON-отчёты. Остальные три работы пока справочные: автоматические расчёты водоснабжения и канализации не добавлены.

Новый веб-отчёт содержит `workPrices: { revision, floorHeatingRubPerM2, insulationRubPerM2 }`. Это снимок применённых расценок, а не ссылка на изменяемые настройки. Коды `FH_INSTALLATION_PRICE` и `FH_INSULATION_PRICE` описывают фактические цены; суммы округляются по каждой работе до копейки в десятичной арифметике. Версия цен не является версией всех инженерных правил: редактор норм остаётся отдельной задачей.

Чистый модуль поддерживает `calculateHeating(input, workPrices?)`. Вызов без второго аргумента и автономный CLI сохраняют прежние нормы из `src/config.ts` и формат отчёта; CLI не подключает SQLite и не использует цены из веб-редактора. Для воспроизведения нового веб-расчёта передавайте его `input` и сохранённый `workPrices`.

`GET /api/works` возвращает `{ revision, items }`, где у каждой работы есть `id`, `name`, `unit`, `priceRub`, `appliedToHeating`. `PUT` принимает только `{ baseRevision, prices: [{ id, priceRub }] }` с пятью уникальными ID: `floor_heating`, `insulation`, `water_point`, `sewer_point`, `sewer_main`. Имена/единицы менять нельзя. Неверный ввод — 400, устаревшая версия — 409. При ошибке черновик сохраняется в форме; «Загрузить актуальные цены» запрашивает подтверждение отмены правок. Автоматического восстановления черновика после закрытия вкладки нет.

Начальные значения имеют версию 0 и читаются без записи в БД. Первое фактическое изменение создаёт `work_price_versions` в транзакции. Версии привязаны к `organization_id`, дописываются без изменения прежних; повторное сохранение одинаковых цен не создаёт новую версию. При потере ответа проверьте актуальные цены перед повторным редактированием. Новые backend-маршруты требуют перезапуска локального сервера; рабочую БД при разработке не изменяем.

## Входной контракт расчёта

| Поле | Тип | Назначение |
| --- | --- | --- |
| `houseAreaM2` | положительное число или `null` | Общая площадь дома |
| `rooms` | массив | Можно оставить пустым, если отопление не описано |
| `heatSource` | `gas \| electric \| solid_fuel \| pellet \| unknown` | Источник отопления |
| `availableElectricPowerKw` | число или `null` | Доступная электрическая мощность |
| `residents` | целое ≥ 0 или `null` | Количество жильцов |
| `baths` | целое ≥ 0 или `null` | Количество ванн |
| `showers` | целое ≥ 0 или `null` | Количество душей |
| `includeIndirectWaterHeater` | boolean или `null` | Нужен / не нужен / неизвестно |
| `circuitLengthM` | положительное число или `null`, необязательно | В форме по умолчанию неизвестна; более 80 до 90 м требует проверки, более 90 м невозможно |

Каждое помещение содержит обязательные `id`, `name` и параметры `areaM2`, `ceilingHeightM`, `hasStandardWindows`, `hasPanoramicWindows`, `floorHeatingAreaM2`, `hasRadiator`. Числа и логические параметры могут быть `null`. Для радиаторов `true` означает «есть / нужен», `false` — «нет / не нужен», `null` — «неизвестно».

Пропущенные расчётные параметры нормализуются в `null`, пропущенные помещения — в пустой массив, источник тепла — в `unknown`. Пустая строка в JSON не считается числом. В форме пустая длина контура передаётся как `null`: труба и работы рассчитываются, а для количества контуров требуется длина. Только пропущенное поле в старом JSON использует норму 80 м для обратной совместимости. Источник по умолчанию не указан (`""`); это не означает «Инженер».

### Частичный расчёт

Каждый блок рассчитывается независимо при достаточных данных. Недостаток данных даёт ему статус `impossible` и список путей `missingParameters`; неизвестные результаты остаются `null`. Остальные блоки продолжают рассчитываться. В одном блоке также могут оставаться известные результаты: например, труба и работы по ТП при неизвестном количестве смесительных узлов.

Старые полные JSON продолжают поддерживаться, сохранённые версии отчётов не пересчитываются при чтении. На новой карточке нет вымышленных помещений и предзаполненных исходных данных. Карточку без расчёта по-прежнему можно сохранить.

Суммы — **стоимость известных работ** (монтаж ТП и укладка утеплителя), не полная стоимость отопления. Цены материалов не заданы: материалы не считаются бесплатными. Неопределённый бойлер не является выбранным товаром.

## Статусы

Статусы расчёта:

- `calculated` — применены известные правила;
- `requires_engineer_review` — правило неполное или требуется инженерное решение;
- `impossible` — входное сочетание нельзя рассчитать по допустимым правилам.

Статусы проверки введённых параметров: `unverified`, `confirmed`, `requires_engineer_review`. Источники: `client`, `engineer`, `project_document` или пустое значение (не указан). Источник и подтверждение независимы.

Вычисленные параметры получают источник `calculation` и статус соответствующего расчётного блока. `calculated` означает выполнение расчёта по правилам, а не утверждение инженером.

Сейчас общий источник и статус применяются ко всем полям новой версии. Индивидуальное редактирование метаданных, выбор старых версий в интерфейсе, защита несохранённых изменений и выбор существующего клиента отложены до отдельного согласования.

Общий статус отчёта равен самому строгому статусу вложенных результатов. Отчёт также содержит коды применённых правил, предупреждения и ошибки.

## Принятые ограничения

- Приложение предназначено только для локальной проверки. Перед внешним размещением нужна авторизация.
- SQLite подходит для текущего однопользовательского режима. Доступ к данным отделён интерфейсом репозитория для последующего перехода на PostgreSQL.
- Площадь помещений может быть меньше площади дома: допускаются ещё не внесённые помещения.
- Панорамное окно или потолок выше 3,2 м запрещает автоматический расчёт мощности радиатора в этом помещении.
- Наличие бойлера косвенного нагрева переводит предварительный выбор мощности котла на проверку инженера.
- Для твердотопливного и пеллетного источника ТЗ не задаёт таблицу мощности, поэтому решение принимает инженер. Неизвестный источник — недостающий параметр для выбора котла.
- Материалы котельной, трубы, фитинги и конкретные товары не рассчитываются: этих правил нет в ТЗ версии 1.0.
