# Локальное приложение ИВОК

Реализация **TASK-01** и локального этапа **TASK-02** из `Task.md`:

- детерминированный расчёт отопления;
- карточки клиентов и объектов;
- сохранение версий расчётов в SQLite;
- источник и статус каждого входного и вычисленного параметра;
- веб-интерфейс и CLI расчётного ядра.

Авторизация, AI, интеграции и подбор товаров пока не используются.

## Требования

- Node.js 22.13 или новее (для встроенного модуля SQLite);
- npm.

В окружении с `NODE_ENV=production` установите зависимости разработки явно:

```bash
npm install --include=dev
```

## Веб-приложение

Запустите локальный сервер:

```bash
npm run web
```

Откройте в браузере:

```text
http://127.0.0.1:3000
```

Сервер намеренно принимает подключения только с локального компьютера. Другой порт можно задать переменной `PORT`.

В интерфейсе можно:

1. создать карточку клиента и объекта — обязательны только имя клиента и адрес объекта; карточку можно сохранить без расчёта;
2. заполнить помещения и исходные параметры;
3. указать общий источник и статус введённых параметров;
4. сохранить расчёт;
5. открыть сохранённый объект, отредактировать карточку и добавить новую версию расчёта;
6. посмотреть источник и статус каждого сохранённого параметра.

В списке объектов отображается статус последнего расчёта или «Без расчёта». На экранах шириной до 640 px список по умолчанию свёрнут; кнопка «Показать объекты» открывает его. После выбора объекта список сворачивается.

По умолчанию база находится в `data/ivok.sqlite`. Путь можно изменить переменной `IVOK_DATABASE_PATH`. Каталог `data/` не сохраняется в Git.

Остановить сервер можно сочетанием `Ctrl+C`.

## HTTP API

| Метод и адрес | Назначение |
| --- | --- |
| `GET /api/objects` | Список сохранённых объектов |
| `POST /api/objects` | Создать клиента и объект; первый расчёт можно передать необязательно |
| `GET /api/objects/:id` | Получить карточку и все версии расчётов |
| `PATCH /api/objects/:id` | Изменить карточку клиента и объекта |
| `POST /api/objects/:id/calculations` | Добавить версию расчёта |
| `POST /api/calculate` | Выполнить расчёт без сохранения для обратной совместимости |

Все основные сущности сохраняют `organization_id`. В локальном режиме используется одна системная организация `org-local`.

## Запуск расчёта через CLI

Из файла:

```bash
npm run calculate -- examples/heating-input.json
```

Через stdin:

```bash
cat examples/heating-input.json | npm run calculate
```

Команда печатает отчёт в stdout. Ошибка JSON или входного контракта печатается в stderr, код завершения — `2`.

## Входной контракт расчёта

| Поле | Тип | Назначение |
| --- | --- | --- |
| `houseAreaM2` | положительное число | Общая площадь дома |
| `rooms` | массив | Хотя бы одно помещение |
| `heatSource` | `gas \| electric \| solid_fuel \| pellet \| unknown` | Источник отопления |
| `availableElectricPowerKw` | число или `null` | Доступная электрическая мощность |
| `residents` | целое ≥ 0 | Количество жильцов |
| `baths` | целое ≥ 0 | Количество ванн |
| `showers` | целое ≥ 0 | Количество душей |
| `includeIndirectWaterHeater` | boolean | Нужен ли бойлер косвенного нагрева |
| `circuitLengthM` | положительное число, необязательно | Длина контура; по умолчанию 80 м, 80–90 м требует проверки, более 90 м невозможно |

Каждое помещение содержит `id`, `name`, `areaM2`, `ceilingHeightM`, `hasStandardWindows`, `hasPanoramicWindows`, `floorHeatingAreaM2` и `hasRadiator`.

## Статусы

Статусы расчёта:

- `calculated` — применены известные правила;
- `requires_engineer_review` — правило неполное или требуется инженерное решение;
- `impossible` — входное сочетание нельзя рассчитать по допустимым правилам.

Статусы введённых параметров дополнительно включают `unverified` и `confirmed`. Источники: `client`, `engineer`, `project_document`; вычисленные параметры получают источник `calculation`.

Общий статус отчёта равен самому строгому статусу вложенных результатов. Отчёт также содержит коды применённых правил, предупреждения и ошибки.

## Принятые ограничения

- Приложение предназначено только для локальной проверки. Перед внешним размещением нужна авторизация.
- SQLite подходит для текущего однопользовательского режима. Доступ к данным отделён интерфейсом репозитория для последующего перехода на PostgreSQL.
- Площадь помещений может быть меньше площади дома: допускаются ещё не внесённые помещения.
- Панорамное окно или потолок выше 3,2 м запрещает автоматический расчёт мощности радиатора в этом помещении.
- Наличие бойлера косвенного нагрева переводит предварительный выбор мощности котла на проверку инженера.
- Для твердотопливного, пеллетного и неизвестного источника ТЗ не задаёт таблицу мощности, поэтому решение принимает инженер.
- Материалы котельной, трубы, фитинги и конкретные товары не рассчитываются: этих правил нет в ТЗ версии 1.0.
